# Sampled playback work correlation (#123, Movly #650)

The captured reporter exposes correlation only for a sampled, currently owned, undisposed attempt. Cold/negative capability and positive unsampled attempts expose none. The API accepts this narrow context only on source discovery, resume lookup and playback creation. Existing expected-owner headers and context generation remain authoritative; a disposed or replaced correlated request cannot publish its late response.

After authentication and expected-owner checks, the BFF validates exactly 32 lowercase hexadecimal characters. It forwards that value only to explicitly selected controlled API work, keeping each API request's independent request ID. It never puts correlation into provider resolver arguments, outbound provider/media headers, media options, session storage, telemetry body extensions or metric labels. Invalid/missing correlation does not change routing, status or payload.

Each correlated BFF request has a stateless accumulator: at most eight first-occurrence spans, 1024 encoded header bytes, and 120000 ms per duration. Closed host-local names are `bff_source_discovery` (this caller's cached/shared search wait), `bff_source_resolve`, `bff_session_prepare`, `bff_init`, and `bff_probe`. The aggregate prepare span contains its init/probe children; do not add or subtract overlapping durations as a distributed wall-clock trace. Closed outcomes are success/failure/timeout/cancelled. No new await, queue, background delivery or retained diagnostics store is added.

Go `movly_profile_policy`, `movly_stream_read`, and `movly_probe_wait` spans are admitted only with the matching admitted response echo, closed duration/outcome grammar and bounded upstream header. Other entries, arbitrary descriptions and overbudget headers are ignored. An optional observer failure does not become an authentication or playback decision. Responses carrying timings are private/no-store. The browser can inspect Server-Timing on the same-origin work response; no new UI dashboard is claimed.

Validation includes real browser imports of the production reporter/API, actual HTTP BFF→synthetic controlled upstream, separate synthetic provider HTTP without correlation/auth leakage, actual playback start/ffprobe with independently held resolve/media work, strict owner/lifetime cases and the existing web suite. The retained private proof intentionally contains only synthetic result classifications and closed timings. This does not establish live Go instrumentation, native client adoption, historical internal dashboards, or a displayed video frame; those remain separate parent #650 acceptance.

Unsuccessful startup terminals (failure/timeout/cancelled/source_switch) freeze later phases, failure/switch observations and correlation access. Successful Playing/FirstFrame startup still allows its separate later failure/switch slots. Terminal/later event durations use the same monotonic snapshot as elapsed time. Regression #125 was reproduced before the fix with deterministic clocks and all three unsuccessful terminal outcomes.
